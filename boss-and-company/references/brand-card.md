# 小白品牌名片快速路径

适用对象：想要一个 GitHub 个人主页 + 个人网站来展示自己，但**没有简历、没有现成项目、不懂 GitHub Pages / gh / Harness** 的用户。目标是一句话触发后，AI 带着用户走完，最终拿到两个能打开的真实链接：`https://github.com/<owner>` 的主页 README，以及个人网站 URL。

这是 [初始化流程](initialization.md) 的**快捷入口**，不是另一套系统。它把标准流程翻译成小白语言并减少提问；凡是本文件没说的，仍按 [初始化](initialization.md)、[展示与部署](publishing.md)、[术语契约](glossary.md) 执行。术语冲突时以术语契约为准；用户最新指令与宿主权限始终最高。

## 一句话触发

下列说法都应直接进入本路径，而不是反问"要不要初始化公司"：

- 「帮我在 GitHub 做个个人名片 / 主页 / 个人网站 / 作品集」
- 「我想让别人搜到我，做个能展示我的网站」
- 「我没有简历，帮我从零做一个介绍自己的页面」
- 英文：`make me a GitHub profile / personal website / portfolio`

进入路径后先判断：是否已连接可写 GitHub 的账号/工具。没有则明确告知缺什么、请用户授权或登录，**不要假装已创建**。

## 最小信息收集（无简历也能开始）

小白可以什么都还没有。AI 通过**几轮简短问答**收集下面这些，收集到够用的最小集就动手，不追求一次问全：

| 信息 | 是否必需 | 怎么问（小白语言） |
| --- | --- | --- |
| 称呼 / 昵称 | 必需 | 「别人平时怎么称呼你？」 |
| 一句话自我介绍 | 必需 | 「用一句话说说你是做什么的？」 |
| 身份方向 | 必需 | 「学生 / 开发者 / 设计师 / 求职者 / 其他？」 |
| 3 个关键词或技能 | 建议 | 「你最想让人记住的 3 个词是什么？」 |
| 联系与社交链接 | 建议 | 「有想放上去的邮箱 / 博客 / 社交链接吗？没有可跳过」 |
| 1 个代表经历或作品 | 可选 | 「有没有一件拿得出手的事？没有也没关系，先留空」 |

提问纪律：

- **一次最多问 2–3 个问题**，不要一次甩一张表给用户。
- 用户说"没有 / 跳过 / 不知道"就接受，用占位或省略，不反复追问。
- 用户已有简历、GitHub 资料或项目链接时，优先从这些材料提炼，减少提问；提炼规则见 [资料规则](passport.md)。
- 收集到的信息先进 private 老板档案的草稿；**公开前必须让用户确认哪些能公开**。

## 隐私与公开边界（小白最容易踩坑）

- 不因为"是基础信息"就默认公开姓名全称、邮箱、电话、城市、学校、履历细节；逐项确认后再写进公开页面。
- 不把私有仓库、密钥、认证文件、聊天原文放进任何公开产物。
- 生成的主页 README 和网站源码里不能藏 HTML 注释、隐藏字段或 JSON 夹带隐私。
- 隐私规则的完整定义见 [展示与部署](publishing.md) 和 [资料规则](passport.md)。

## 自动生成与部署

信息够用且公开范围确认后，按现有能力自动完成，不需要用户理解内部步骤：

1. **建/复用仓库**：`owner/owner` 作为主页仓库（public），独立网站仓库或复用已有网站（public）。已有主页时按两问决定 keep/replace，默认 keep；已有网站默认 reuse。小白场景两问要用大白话重述（"你 GitHub 上已经有主页了，要覆盖还是保留？"），并把选择记下来，不重复问。
2. **生成内容**：把收集到的信息整理成规范化档案，交给 `scripts/render.py` 用内置模板生成主页 README 与网站。模板现在是**开发者向**视觉风格；没有作品时允许只呈现"身份 + 简介 + 关键词 + 链接"的最小名片，不从空白编造项目或经历。
3. **部署**：新站默认 GitHub Pages，通过 `assets/templates/pages.yml` 工作流部署；写入默认分支后启用 Pages 的 Actions 来源，等构建与部署成功，打开真实 URL 复核。缺管理权限时如实报告待办，不绕过。
4. **回读验证**：主页 README 内容与网站 URL 可访问分别确认；"生成了文件""提交了工作流""部署成功""链接打得开"是四个不同状态，逐个报告。

完整规则见 [初始化流程](initialization.md) 第 3、4、6、8 步和 [展示与部署](publishing.md)。

## 完成后给小白的汇报

用非技术语言说明，避免堆术语：

- 你的主页地址是 `<URL>`，现在别人搜 `github.com/<owner>` 就能看到你的介绍。
- 你的网站地址是 `<URL>`，手机和电脑都能打开。
- 已经公开了哪些内容（逐项列），哪些没有公开。
- 想改内容时，直接跟我说「把网站上的 XX 改成 YY」即可。
- 若某步骤没做成（如 Pages 权限不足），明确说卡在哪、需要用户做什么。

## 与「个人公司」完整能力的关系

名片路径是入口，不是终点。用户拿到名片后，可以继续使用完整能力：登记项目、跨 AI 协作留痕、阶段汇报、跨会话交接、"最近在忙"动态展示。是否启用这些由用户决定；**默认只做名片，不擅自建一堆 private 仓库或打开自动写入开关**。相关说明见 [主动性开关](automation.md)。
